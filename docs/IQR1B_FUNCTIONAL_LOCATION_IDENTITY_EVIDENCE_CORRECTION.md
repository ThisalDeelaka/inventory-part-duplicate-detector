## General bounded abstraction

`functional-location-facet-v1` represents a source-aware facet with an axis,
value, qualifier-free shared construct, source family, matched normalized
evidence, and versioned provenance. The initial deliberately small ontology is
the `longitudinal_end` axis with incompatible `head` and `tail` values.

Extraction requires the qualifier to modify a following explicit construct and
comparison requires both records to expose incompatible values on the same axis
and the same exact shared construct. It is therefore not a noun-specific
Head-Light/Tail-Light rule and does not treat an isolated token as a conflict.
For example, terminal `head` in `B38 Engine Head` is not extracted as a location
facet. One-sided evidence also cannot invent a contradiction.

The active GF4 evaluator converts a proven two-sided disagreement into the
existing protected `CANNOT_LINK` mechanism with provenance
`EXPLICIT_TWO_SIDED_FUNCTIONAL_LOCATION_FACET`. The R15 identity-signature seam
and R16 signed-evidence shadow preserve the same typed values and source
observations. No retrieval, budget, resolver-policy, schema, API, UI, export
shape, confidence, or provider behavior changed.
